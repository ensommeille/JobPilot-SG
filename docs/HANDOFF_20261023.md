## Setup and migrations

- Install updated backend dependencies with `python -m pip install -e ".[dev]"`
  from `backend/`. New dependencies include `pypdf` and `python-multipart`.
- On an explicitly selected local database, back up existing data, then run
  `python -m alembic upgrade head` from `backend/`. The new revisions are `0005`
  (source scheduling), `0006` (email), `0007` (PDF files), and `0008` (AI runs).
  Do not stamp an unrelated or deployed database to reproduce this handoff.
- The refresh scheduler is a separate worker:
  `python -m app.ingestion.scheduler --loop --actor-id ADMIN_UUID --poll-seconds 60`.
  No hosted or OS scheduler has been installed; the worker must remain running.
- Email delivery defaults to disabled. The implemented pilot supports only
  `JOBPILOT_EMAIL_MODE=test_smtp`, a numeric loopback SMTP host and a fixed `.test`
  recipient. See the source/email guide for mailbox and workspace commands.
  It does not send to real employers.
- AI defaults to disabled. Normal app execution requires an explicit
  `AI_RECOMMENDATIONS_LIVE_ENABLED=true`, configured `LLM_PROVIDER` and an operator's
  own `LLM_API_KEY`; `LLM_MODEL` is optional. This consumer defaults to
  `deepseek-flash`, zero transport retries, a 60-second timeout and 12,000 output
  tokens. Do not commit a key or copy one from a chat into a repository file.

The ordinary `scripts/local_feature_workspace.py` deliberately disables all live
models. To test AI on an owned local workspace, stop that API and instead run:

```text
python scripts/local_ai_workspace.py --workspace ABSOLUTE_OWNED_WORKSPACE --audit-directory ABSOLUTE_PRIVATE_AUDIT_DIRECTORY --allow-live-ai --max-live-calls 1
```

It prompts for the operator's key with hidden input. The audit directory contains
private professional text and raw model results: keep it outside the checkout.
Use the source guide to create and collect a new workspace first. Build the
frontend with `VITE_API_BASE_URL=http://127.0.0.1:18523`, then serve its preview on
port `15523`. Register an ordinary test account, review and save a PDF-derived
profile, load candidates, select up to five jobs and explicitly confirm analysis.
On helper restart, sign in again; the temporary JWT secret changes.

## Remaining boundaries

- The data-pipeline overclaim above is an actual unresolved semantic defect.
- Missing availability or unlisted skills remain unknown, not proof of inability.
  Fifteen of the final 56 rows describe future duties; unknown counts are not a
  match score or a list of defects.
- These five jobs were a selected acceptance sample, not proof of the best five
  recommendations across the full catalog.
- Only saved JD text is compared. Additional employer application-form conditions
  still need a separate check. Job requirements have not been extracted for every
  stored posting by this work.
- Narrow evidence rules do not prove arbitrary AND/OR, negation or professional
  experience inference correct. Invalid future model output is still rejected;
  failed/expired cache entries do not automatically trigger a paid retry.
- Scanned PDFs need manual transcription; OCR is absent. Long or unusual layouts
  can require review. See the PDF guide for the other known parser/flow limits.
