## English text for the report

Our GitHub Actions CI validated the repository structure and Docker Compose configuration, ran backend Ruff linting, 1,848 backend unit/API tests (90.11% branch-aware coverage), Semgrep SAST (0 findings across 293 rules and 119 targets), project-scoped `pip-audit` (no known vulnerabilities), frontend ESLint, build and npm audit (0 vulnerabilities at the configured threshold), extension checks, an isolated application journey and a Docker smoke check. We retained the [Ruff SARIF](https://github.com/ensommeille/JobPilot-SG/actions/runs/40622693753/artifacts/12788396786), [coverage XML](https://github.com/ensommeille/JobPilot-SG/actions/runs/40622693753/artifacts/12787589015), [Semgrep SARIF](https://github.com/ensommeille/JobPilot-SG/actions/runs/40622693753/artifacts/12788311573) and [application journey evidence](https://github.com/ensommeille/JobPilot-SG/actions/runs/40622693753/artifacts/12787732927) as downloadable artifacts. The test count and frontend checks are in the run logs. A subsequent workflow change adds JUnit XML and frontend lint JSON artifacts; these are **pending a successful run of that change**.

The separate Security Scans workflow ran an OWASP ZAP baseline against the public `/jobs` API, Checkov against the two Dockerfiles, and Trivy against the backend image. Checkov improved from a previously recorded 90 passes/4 failures to [113 passes/0 failures](https://github.com/ensommeille/JobPilot-SG/actions/runs/40622693826/artifacts/12788340825) after both Dockerfiles gained a health check and non-root user in [PR #67](https://github.com/ensommeille/JobPilot-SG/pull/67). The same PR added HTTP security headers; the [ZAP re-scan](https://github.com/ensommeille/JobPilot-SG/actions/runs/40622693826/artifacts/12787872108) reported 0 failures, 1 remaining cacheability warning on 404 pages and 67 passes. Its target and spider scope do not cover authenticated features or employer sites. The [first downloadable Trivy SARIF on PR #68](https://github.com/ensommeille/JobPilot-SG/actions/runs/40691560445/artifacts/12816284892) contains **2 HIGH** findings: the previously reported `libacl1` issue and a newly detected pip-vendored `msgpack` issue. The latter is absent from the application dependencies; PR #68 removes pip from the runtime image after installation. The post-fix SARIF is pending and must be checked before describing that finding as closed. Eleven other IDs remain suppressed by `.trivyignore`, not fixed.

Our security triage keeps the before-scan files, the fix pull requests and re-scan links together in [`docs/security/README.md`](README.md). The initial `pip-audit` snapshot contained 25 findings across six packages; after [PR #58](https://github.com/ensommeille/JobPilot-SG/pull/58), the project-scoped CI audit found none. An older whole-environment after-snapshot still contains five findings in three CI-toolchain packages, so it is not used as evidence of a clean whole environment. The remaining ZAP warning and the reported `libacl1` issue stay open for owner review and re-scanning. Scan success is not the same as vulnerability closure.

Our deployment definitions are Dockerfiles and Docker Compose. They make the local database, Redis, backend, frontend and optional scheduler reproducible; `docker compose config -q` passed on 28 October and also runs in CI. This is **local declarative deployment**, not verified cloud infrastructure as code. We have not provisioned cloud network, managed storage, secrets, autoscaling or a release environment from Terraform/Pulumi. The Checkov job tests Dockerfile policy, not a cloud IaC plan. Details and a future cloud-IaC boundary are in [`docs/deployment/IAC_STATUS.md`](../deployment/IAC_STATUS.md).
