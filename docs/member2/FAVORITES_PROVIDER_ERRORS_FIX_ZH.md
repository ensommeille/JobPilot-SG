# 收藏分页与模型错误提示修复（2026-10-22）

基于 main `4b1e543` 的独立修复，不依赖尚未合并的 #42/#45。

## 用户可见变化

- Saved Jobs 每页 20 条，读取服务器 total/pages，支持 Previous/Next，可访问第 21 条及后续收藏。
- 取消收藏后重新读取列表与数量；删除最后一页的最后一条会回到有效页；前面的页面会补齐下一条。
- 加载失败可 Retry；取消收藏失败保留卡片并提示重试。切换账号/退出时清空列表并取消旧请求，避免旧响应更新新账号的页面。

## 模型错误处理

共享 OpenAI-compatible transport 为 DeepSeek/Qwen 统一提供安全错误分类。新增类别一路保留到抽取运行、管理员接口和两个批处理命令；不存储或返回原始 Provider 错误正文。

| HTTP 状态 | 安全错误码 | 操作提示 |
|---|---|---|
| 401 / 403 | `provider_authentication_error` | 检查服务端密钥与权限 |
| 402 | `provider_insufficient_balance` | 检查账户余额/额度后再重试 |
| 400 / 422 | `provider_invalid_request` | 检查模型与请求参数 |
| 429 | `provider_rate_limit` | 等待限流解除后重试 |
| 其他 4xx，如 404 | `provider_capability_error` | 检查模型、接口地址与能力 |
| 超时 | `provider_timeout` | 先核查运行结果；超时不代表没有用量 |

`extract_saved_jobs` 和 `prepare_jobs` 遇到鉴权、余额、参数、能力或限流错误时停止当前批次，避免对后续岗位重复发起无效调用。CLI 每条记录以及管理员抽取详情/历史接口新增可空的 `error_message`。该字段由固定错误码生成，不包含密钥、个人资料或 Provider 原始响应。

成功记录、严格 schema 校验和普通用户推荐规则保持原有语义。历史笼统错误不反推成某个确定 HTTP 状态；旧记录可以显示通用的能力错误提示。
