# 推荐岗位排序改进说明（2026-10-20）

## 这次解决的问题

原有排序先看是否存在明确技能缺口，再按“出现了多少种具体技能重合”排序。这样会把「三个要求里只是部分提到技能、其余条件尚未核实」的岗位排在「两个要求与个人资料中的技能明确对应」的岗位前面。用户可能误以为前者有更可靠的匹配证据。

## 已完成

- 保留原有的谨慎边界：只比较资料中肯定提及的具体技能与有效岗位要求；没有证据时不制造推荐，也不把推荐解释成符合所有申请条件。
- 排序改为：**无明确技能缺口 → 明确对应的不同技能数量 → 包含部分重合的不同技能总数量 → 岗位新近程度**。同义词、重复要求和笼统软技能不能重复加分。
- 新增回归测试：用「2 项明确对应」与「3 项只部分提及」的岗位对比，证明旧算法顺序不合理，并确认新算法将证据更强的岗位排在前面。
- 更新推荐区文字：解释排序依据；岗位要求数据缺失时明确说明这不是用户资料不合格。
- 同步更新推荐接口契约文档。

## 验证结果

- 后端全量测试：730 通过、1 跳过（本机没有 Docker CLI）；另有 2 项第三方库弃用警告。
- 前端构建及代码检查通过；后端 Ruff 检查及格式检查通过。
- 推荐页面的 9 项浏览器交互测试通过。

## 仍需注意

本机演示数据库目前只有 2 条岗位、0 条可用的岗位要求提取结果。因此这次改进会在有有效提取证据时改善顺序，**不会凭空让当前演示数据产生推荐**。要在真实岗位上看到推荐，还需完成岗位抓取/导入和非 mock、有效且与岗位当前内容一致的要求提取。

组员另有未合并的「项目经历纳入推荐依据」分支。这次没有覆盖那项工作；合并时应保留两边能力，并重跑推荐测试。
