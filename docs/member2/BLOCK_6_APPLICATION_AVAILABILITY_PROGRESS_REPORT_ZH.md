# Member 2 第六板块进展报告 申请助手可用性

**负责人：** LIAO BINGFENG

**职责：** 后端核心和数据库

**日期：** 2026-10-13

**关联 Issue：** [#24 Expose AI form availability per job](https://github.com/ensommeille/JobPilot-SG/issues/24)

## 完成结论

本板块修正了职位详情页对 AI 申请助手可用性的表达。项目提案规定 Phase 1 只在选定的演示职位上使用平台内嵌仿真表单；真实 InternSG 职位继续提供原始页面链接，不应被描述为已经配置了平台内申请表单。

后端现在会在每条职位响应中返回 `assistant_form_available`。前端仅在该值为 `true` 时显示 AI Assistant 按钮，没有表单的真实职位只保留原始职位链接和说明文字。

## 后端修改

- 为 `JobPosting` 增加只读可用性属性，仅在关联的 fixture 表单存在时返回 `true`；
- 在 `JobRead` API 契约中增加 `assistant_form_available` 布尔字段；
- 职位列表、职位详情和收藏查询均预加载表单关系，避免序列化时产生 N 加 1 查询；
- 收藏响应中的嵌套职位使用同一字段，保证各页面判断一致。

## 前端衔接

- 职位详情页读取后端可用性字段；
- 有演示表单时显示 `Apply with AI Assistant`；
- 没有表单时不再展示会进入不可用页面的按钮；
- 真实来源职位仍可通过 `View Original Posting` 打开原始页面。

## 范围判断

本次没有为真实 InternSG 职位伪造雇主申请表单，也没有自动向第三方网站提交数据。该处理符合以下既定范围：

1. Phase 1 使用项目可控的平台内嵌仿真表单；
2. 真实岗位提供详情和外部链接；
3. 第三方页面自动填表属于 Phase 2 浏览器扩展范围；
4. 所有最终提交动作必须由用户触发。

## 验证范围

- 有 fixture 表单的职位返回可用状态；
- 没有表单的职位返回不可用状态；
- 分页职位列表、职位详情和收藏嵌套职位均返回一致结果；
- 前端构建和 lint 验证条件渲染；
- 完整后端测试、覆盖率、Ruff 和 Semgrep 回归检查。

## 团队后续事项

- M1 可继续优化无表单职位的外部申请提示，但不应重新显示不可用的助手按钮；
- M4 可继续改进演示表单的映射质量，不需要为每条实时采集职位生成虚构表单；
- M5 应将前端依赖审计加入维护计划。2026-10-13 本地 `npm audit` 检出两个高危传递依赖告警，均提供可用修复，且不是本板块新增依赖。
