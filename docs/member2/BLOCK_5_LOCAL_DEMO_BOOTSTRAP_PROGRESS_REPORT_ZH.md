## 1. 本板块目标

项目已有数据库结构、认证、职位查询、个人资料及申请助手边界，但全新环境在完成数据库迁移后仍然没有可登录的管理员和可供演示的数据。本板块增加一个安全、可重复执行的初始化入口，让组员首次启动后可以立即演示核心流程，而不需要手工编写 SQL。

## 2. 已完成工作

### 2.1 管理员初始化

- 支持创建新的管理员账号；
- 支持将已有普通求职者账号提升为管理员；
- 已有账号默认保留原密码，仅在显式使用重置选项时更新；
- 如果账号被停用，执行初始化时恢复为可用状态；
- 自动补齐缺失的用户资料记录。

### 2.2 Sandbox 演示数据

- 创建 `JobPilot Sandbox` 数据源；
- 创建两条新加坡职位样例，覆盖实习与全职场景；
- 创建技能及雇佣类型标签，并建立职位—标签关系；
- 为演示职位创建申请表单 fixture，包括姓名、邮箱、教育、经验和求职动机字段；
- 记录 `demo.seed` 审计日志，保留每次执行的创建统计。

### 2.3 幂等性与安全控制

- 多次执行不会重复创建管理员、数据源、职位、标签或表单；
- 管理员密码不作为命令行参数，避免进入 shell 历史；
- 密码只从临时环境变量读取，未提供时使用隐藏式交互输入；
- 命令输出仅包含非敏感统计，不打印密码或密码散列；
- 初始化过程在同一数据库事务内执行，失败时统一回滚。

## 3. 使用方法

在 `backend` 目录完成依赖安装和数据库迁移后执行：

```bash
export JOBPILOT_DEMO_ADMIN_PASSWORD='请替换为至少 8 位的本地密码'
python -m app.demo_seed --admin-email admin@jobpilot.sg
unset JOBPILOT_DEMO_ADMIN_PASSWORD
```

如需显式重置已有账号密码：

```bash
python -m app.demo_seed \
  --admin-email admin@jobpilot.sg \
  --reset-existing-password
```

没有设置环境变量时，程序会在终端中隐藏输入密码。

## 4. 验证范围

自动化测试覆盖以下场景：

1. 首次执行能创建完整演示数据；
2. 第二次执行不会产生重复业务数据；
3. 已有普通用户能提升为管理员，且原密码默认不变；
4. 显式重置选项能更新已有账号密码；
5. 命令从环境变量读取密码，输出中不泄露敏感信息。

## 5. 对团队的价值

- 前端成员可直接使用演示职位、标签和表单联调；
- M4 申请助手可使用稳定的 fixture 验证字段映射；
- 测试和展示环境能通过同一个入口重建，减少“只在某台电脑可运行”的问题；
- 管理员接口不再依赖手工修改数据库角色。
